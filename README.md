# 논물관리(AWD / 중간물떼기) 이행 검증

무료 위성 데이터로 논의 담수·낙수를 판별해 **연속 낙수 14일 이상** 기준
충족 여부를 판정합니다. 농가 신고나 현장 방문 없이 필지 단위로 확인합니다.

Sentinel-1 SAR(C-band, 10 m)로 판정하고, NISAR(L-band)로 교차검증합니다.
구름·야간과 무관하게 관측되므로 장마철에도 끊기지 않습니다.

```bash
python paddy_check.py --lat 35.9820 --lon 126.9250 --year 2026
```

웹 화면으로도 쓸 수 있습니다 — 지도에서 논을 클릭하고, CSV로 수백 필지를
한 번에 돌리고, 결과를 그래프·리포트로 받습니다.

## 먼저 알아야 할 한계

이 도구는 **1차 스크리닝**용입니다. 행정 처분의 최종 근거로 쓰기에는
아래 한계가 있습니다. 리포트에도 매번 함께 출력됩니다.

- **캐노피 차폐** — 벼가 자라면 잎이 수면을 가려 담수 상태도 낙수로 보입니다.
  같은 필지가 분석 기간에 따라 이행(60일)/미이행(12일)으로 갈리는 것을
  실측으로 확인했습니다. 그래서 기본 기간이 **5/1 – 7/20**입니다.
- **임계값** — 기본 −20 dB는 문헌 경험값이며 한국 논으로 보정한 값이 아닙니다.
  경계 사례에서는 0.5 dB 차이로 판정이 뒤집힙니다(자동 경고 표시).
- **관측 간격** — 위성이 지나갈 때만 관측되므로 낙수 시작·종료 시점에
  최대 ±18~24일의 불확실성이 있습니다.
- **논 여부 미검사** — 논이 아닌 좌표를 넣어도 그럴듯한 판정이 나옵니다.
  결과 그래프에서 논다운 신호가 보이는지 먼저 확인하세요.

자세한 근거와 실측값은 [과학 레퍼런스](#판정-원리와-한계)를 참고하세요.

## 웹 화면으로 쓰기 (권장)

```bash
cd ~/paddy-awd-check && .venv/bin/python web/app.py
```

브라우저에서 http://127.0.0.1:8000 으로 접속합니다. 세 개 탭이 있습니다.

- **단건 분석** — 위성사진 지도에서 논을 클릭해 좌표를 찍고 실행. 진행 상황이
  실시간으로 흐르고, 끝나면 판정·그래프·임계값 민감도표가 나옵니다.
- **일괄 분석** — `이름,위도,경도` CSV 를 끌어다 놓으면 순서대로 처리하며
  표를 채웁니다. 요약 CSV 로 내려받을 수 있습니다.
- **지난 결과** — `output/` 에 쌓인 과거 실행 결과 목록.

`paddy_check.py` 를 그대로 호출하는 얇은 래퍼라 분석 로직은 CLI 와 완전히 같습니다.

### 임계값 민감도

단건 분석 결과에는 임계값을 ±1 dB 흔들었을 때 판정이 어떻게 변하는지가 함께
나옵니다. 판정이 뒤집히면 **경계 사례 경고**가 뜹니다 — 위성만으로 단정하기
어려운 필지이니 현장 확인이 필요하다는 뜻입니다.

### 여럿이 같이 쓸 때

비밀번호를 걸고 외부 접속을 열 수 있습니다.

```bash
PADDY_WEB_PASSWORD=원하는비밀번호 .venv/bin/python web/app.py --host 0.0.0.0
```

비밀번호를 설정하지 않으면 인증 없이 열리므로, `--host 0.0.0.0` 을 쓸 때는
반드시 함께 설정하세요. 현재는 서버에 저장된 Copernicus 계정 하나로 모든
사용자의 요청을 처리합니다.

## 명령줄로 실행

```bash
python paddy_check.py --lat 36.3721 --lon 127.3604 --year 2025
```

최초 실행 시 터미널에 로그인 URL과 사용자 코드가 표시됩니다. 브라우저에서
Copernicus Data Space 계정으로 로그인하면 인증이 완료되고, refresh token 이
저장되어 이후 실행에서는 생략됩니다.

결과는 `output/` 에 PNG 그래프와 마크다운 리포트로 저장됩니다.

### 인증이 자꾸 끊길 때

openeo 클라이언트는 승인 대기 폴링 중 일시적인 네트워크 오류가 한 번만 나도
인증 전체를 중단합니다. 회선이 불안정하면 재시도 내성이 있는 별도 스크립트로
먼저 인증하세요.

```bash
python auth_setup.py
```

refresh token 이 `~/Library/openeo-python-client/refresh-tokens.json` (macOS) 에
저장되며, 이후 `paddy_check.py` 는 이를 그대로 사용합니다.

### 인증이 만료되면

이 토큰은 며칠 쓰지 않으면 만료됩니다(`400 invalid_grant / Stale token`).
만료된 상태로 실행하면 **분석 시작 몇 초 안에 그 사실을 알려주고 멈춥니다.**
웹 화면에서는 접속하자마자 상단에 붉은 배너가 뜹니다.

```bash
python auth_setup.py
```

무인 환경(웹 서버, 스케줄러)에서는 `--non-interactive` 를 주세요. 아무도
로그인 코드를 입력할 수 없는 곳에서 대화형 흐름으로 넘어가 기다리는 일을
막습니다. 웹앱은 항상 이 옵션으로 실행합니다.

서버로 상시 운영한다면 개인 로그인 대신 **CDSE 서비스 계정(client_credentials)**
을 쓰세요. 만료가 없고 openEO·Sentinel Hub 두 경로 모두에 적용됩니다.
설정 방법은 [DEPLOY.md](DEPLOY.md) 를 보세요.

### 데이터 경로 (`--source`)

- `auto` (기본): openEO 로 시도하고, 백엔드 장애 시 **Sentinel Hub Statistical
  API 로 자동 폴백**합니다. 같은 CDSE 계정 토큰, 같은 자료(S1 GRD), 같은 보정
  (sigma0-ellipsoid)을 쓰므로 결과가 ±1 dB 이내로 일치합니다.
- `openeo` / `sentinelhub`: 경로 고정.

두 경로의 값이 소폭(±1 dB) 다르므로, 스무딩된 값이 임계값 부근(±0.5 dB)에
걸린 관측이 있으면 경로에 따라 판정이 뒤집힐 수 있습니다. 그런 경계 사례는
임계값을 조정해 민감도를 확인하세요 (`--threshold -19`, `--threshold -21` 등).

### CDSE 백엔드 장애

`503 no available server` 는 CDSE 처리 백엔드의 점검·과부하입니다. 코드 문제가
아니며 재시도(지수 백오프 4회)가 자동으로 들어갑니다. 그래도 실패하면 수십 분
뒤 다시 실행하세요.

버전 협상용 `/.well-known/openeo` 가 죽으면 클라이언트가 HTML 을 서빙하는 루트로
폴백해 `Expecting value: line 1 column 1` 라는 엉뚱한 JSON 파싱 오류를 냅니다.
이 경우 버전 고정 URL(`/openeo/1.2`)로 자동 재접속하므로 별도 조치는 없습니다.

## NISAR L-band 교차 검증

Sentinel-1(C-band, 5.6 cm)은 벼가 자라면 캐노피 산란 때문에 담수 상태여도
후방산란이 올라갑니다. 이게 이 도구의 가장 큰 한계였습니다.

NISAR(L-band, 24 cm)는 파장이 길어 캐노피를 투과하고 **수면-줄기 이중반사**를
봅니다. 담수 상태에서 벼가 자라면 오히려 신호가 강해지므로, C-band 의
과대판정을 잡아낼 수 있습니다.

### 준비

NASA Earthdata 계정(무료)이 필요합니다. https://urs.earthdata.nasa.gov 에서
가입한 뒤 한 번만 로그인하면 `~/.netrc` 에 저장됩니다.

```bash
.venv/bin/python -c "import earthaccess; earthaccess.login(persist=True)"
```

### 사용

웹 단건 분석은 교차 검증을 **기본으로 수행**하며, 결과 화면의 주 그래프가
두 센서를 겹쳐 그린 통합 그래프입니다. 명령줄에서는:

```bash
.venv/bin/python nisar_compare.py --lat 35.9820 --lon 126.9250 --start 2026-05-01 --end 2026-07-20
```

```bash
.venv/bin/python nisar_evidence.py --lat 35.9820 --lon 126.9250 --start 2026-06-17 --end 2026-08-03 --append
```

`nisar_compare.py` 는 통합 그래프를, `nisar_evidence.py` 는 판정 표를 만듭니다.
`--append` 를 주면 기존 S1 리포트 끝에 교차 증거 섹션을 덧붙입니다.

### 통합 그래프 읽는 법

두 센서 값이 모두 후방산란 dB 이므로 **같은 축 하나**에 겹쳐 그립니다
(이중 y축을 쓰지 않습니다). 물리가 반대라는 점이 핵심입니다.

| 신호 | 담수일 때 | 낙수일 때 |
| --- | --- | --- |
| S1 VH (C-band) | 낮음 | 높음 — 단, 캐노피가 자라도 높아짐 |
| NISAR HH (L-band) | 높음 | 낮음 |

따라서 두 선이 **반대로** 움직이면 판정이 맞은 것이고, **같이 올라가면**
C-band 의 상승은 낙수가 아니라 벼가 자란 것입니다. NISAR 를 얻지 못한
기간에도 같은 그래프를 그리고 그 사실을 그래프 안에 적습니다 — "아직 안 해 본 것"
과 "할 수 없는 것"을 구분하기 위해서입니다.

### 판정 방식

절대 임계값이 아직 없으므로 **같은 필지 안의 상대 비교**를 씁니다.

| 결과 | 의미 |
| --- | --- |
| S1 과대판정 의심 | S1 이 낙수라 본 시점의 HH 가 담수 시점보다 **높음** — 물이 차 있었을 가능성 |
| 두 센서 일치 | HH 가 **낮음** — 실제 낙수와 부합 |
| 판단 보류 | 차이가 1 dB 이내이거나 비교 관측이 부족 |

**판정 주체는 여전히 Sentinel-1 입니다.** NISAR 는 그 판정이 캐노피에 속은
것은 아닌지만 점검합니다. 절대 임계값은 낙수 사례를 확보한 뒤에 정할 수 있습니다.

### 관련 스크립트

| 파일 | 역할 |
| --- | --- |
| `nisar_source.py` | 시계열 추출 (부분 읽기 + 캐시). 단독 실행 가능 |
| `nisar_evidence.py` | 교차 증거 생성, 리포트 덧붙이기 |
| `nisar_compare.py` | C-band·L-band 를 한 축에 겹쳐 그린 통합 그래프 |
| `nisar_scan.py` | 낙수 필지 탐색 (임계값 도출용) |
| `nisar_probe.py` / `nisar_phase2.py` | 초기 타당성·물리 검증 (기록용) |

### 제약

- **공개분은 2026-06-17 이후**입니다. 그 이전 기간은 S1 단독 판정만 가능합니다.
- 그래뉼 하나가 5~6 GB 이지만 HTTP range 로 **0.23% 만 전송**합니다
  (실측: 4,923 MB 중 11.3 MB, 19초). 결과는 `output/nisar_cache.json` 에 캐시됩니다.
- Provisional 제품이라 보정값이 바뀔 수 있습니다.
- 궤도(트랙)가 혼재해 수 dB 계통 차이가 있을 수 있습니다.

## 좌표를 먼저 확인하세요

**이 도구는 좌표가 실제 논인지 검사하지 않습니다.** 논이 아닌 곳을 넣어도
그럴듯한 판정이 나오므로, 결과 그래프에서 논다운 신호가 보이는지 먼저
확인해야 합니다. 지표별 VH 값의 대략적 기준은 다음과 같습니다.

| 지표 | VH (dB) |
| --- | --- |
| 개활수면 (호수) | -28 내외 |
| 해수면 | -31 내외 |
| **담수된 논 (이앙기)** | **-22 ~ -27** |
| 생육기 벼 캐노피 | -16 ~ -18 |
| 도심·건물 | -20 이상 |

정상적인 논이라면 **이앙기(5~6월)에 -22 dB 이하로 뚜렷이 내려갔다가 생육기에
걸쳐 -16 dB 부근까지 상승**하는 곡선이 나옵니다. 전 기간 평탄하거나 진폭이
2~3 dB 에 불과하면 논이 아니거나 버퍼에 다른 지물이 섞인 것입니다.

## 옵션

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--lat`, `--lon` | (필수) | 필지 중심 위경도 |
| `--year` | 올해 | 분석 연도 (기간 5/1 ~ 9/30) |
| `--start`, `--end` | — | 기간 직접 지정 (YYYY-MM-DD, `--year` 보다 우선) |
| `--threshold` | `-20.0` | 담수 판정 임계값 (dB). 미만이면 담수, 이상이면 낙수 |
| `--buffer` | `40` | 좌표 주변 버퍼 반경 (m) |
| `--min-days` | `14` | 이행 판정 기준 연속 낙수 일수 |
| `--smooth` | `3` | 이동평균 창 크기 (1이면 스무딩 없음) |
| `--outdir` | `output` | 결과 저장 디렉터리 |
| `--csv` | off | 관측 시계열을 CSV로도 저장 |

예: 임계값을 -19 dB 로 조정하고 기간을 직접 지정

```bash
python paddy_check.py --lat 36.3721 --lon 127.3604 --start 2025-05-01 --end 2025-09-30 --threshold -19
```

## 동작 방식

1. 좌표 주변 반경 40 m 폴리곤 생성
2. openEO 로 `SENTINEL1_GRD` 조회 → `sar_backscatter(sigma0-ellipsoid)` → VH 밴드
3. `aggregate_spatial(mean)` 로 폴리곤 공간평균 시계열 추출, `10*log10()` 으로 dB 변환
4. 3점 중심 이동평균으로 궤도별 노이즈 완화
5. 임계값 기준 관측일별 담수/낙수 분류 (관측 사이 구간은 앞 관측 상태 유지로 간주)
6. 연속 낙수 구간 탐색 → 최장 구간이 기준일 이상이면 "이행"

## 판정 원리와 한계

담수된 논은 경면반사로 후방산란이 매우 낮고, 낙수 후에는 토양·캐노피 산란으로
상승합니다. 다만 다음 한계가 있습니다 (리포트에도 자동 명시됩니다).

- **관측 간격 오차**: Sentinel-1 재방문 주기 때문에 낙수 시작·종료 시점에 며칠의
  불확실성이 있습니다. 지속일수는 관측이 확인된 범위만 세는 보수적 값입니다.
- **임계값 가정**: -20 dB 는 경험값입니다. 지역·품종·입사각에 따라 달라지므로
  인근 상시담수 필지 값을 참조해 보정하는 것이 좋습니다.
- **생육 후기 캐노피 차폐**: 출수기 이후에는 담수 상태여도 낙수로 과대판정될 수 있습니다.
  실측에서도 7월 하순 이후 캐노피 성장에 따른 상승이 그대로 "낙수"로 잡혔습니다.
  중간물떼기 판정은 **이앙 후 ~7월 중순 구간**에 한정해 보는 것이 안전합니다
  (`--start`, `--end` 로 기간을 좁히세요).
